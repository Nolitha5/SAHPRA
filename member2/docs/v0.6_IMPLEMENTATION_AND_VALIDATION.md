# Member 2 Release v0.6 — Extended Technical Retrieval Validation

**Release date:** 19 October 2026  
**Research status:** engineering prototype, **NOT** expert-labelled validation, regulator approval, clinical/quality decision tool, or authorized SAHPRA pilot.  
**Continuation:** v0.5 with all 15 user-supplied regulatory PDF references, original unmodified bytes, SHA-256 source register, 554 anchored passages.

## New work executed

1. Verified all 15 physical PDF source hashes against the v0.5 manifest and confirmed each technical probe anchor occurs within its actual document.
2. Implemented 30 **researcher-created source-navigation questions**, two per document. They target document discovery, not regulatory correctness. Some queries deliberately contain document identifiers and can be easier than genuine assessor questions.
3. Ran five **actual offline indexing/retrieval algorithms** over all 554 real extracted passages without document-ID search filters: BM25, deterministic hash demo, word TF-IDF, character TF-IDF, and RRF hybrid of BM25 + word TF-IDF. This is not dense pretrained BGE retrieval.
4. Implemented a native ChromaDB + SentenceTransformers/BGE verification runner, including SHA-256 source checks, Chroma persistence/reopen/ID checks, actual-model token-length audit and a repeat of the same navigation probes. This runner cannot execute without the real dependencies and weights.
5. Added new regression checks for source coverage, exact page verification, duplicated passage IDs, honest native-preflight status and evaluation labels. **77 automated tests passed.**

### Windows execution with real dependencies

```powershell
cd SAHPRA_Member2_Evaluation_and_Chroma_Readiness_v0.6
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[vector,models,dev,experiment]"
python scripts/run_native_bge_chroma_validation.py --root . --model BAAI/bge-large-en-v1.5
python scripts/run_native_bge_chroma_validation.py --root . --model BAAI/bge-m3 --model sentence-transformers/all-MiniLM-L6-v2
python -m pytest -q
```

Run these commands on an internet-connected device that can obtain the model weights (first use may download substantial model files). `--offline` requires cached weights. Outputs are written into `validation/v0.6_NATIVE_CHROMA_BGE_REPORT.json`, and database data into `artifacts/v0.6/native_chroma/`. This does not replace a domain expert source-approval process.

## Known limitations of the indexed corpus

- Existing 554 chunks use a **whitespace-approximation of 512 tokens**: BGE tokenizer length may exceed model context. Native runner explicitly audits token counts; re-chunk with a fixed model tokenizer (256/512/1024 and overlap) for fair comparative experiments.
- PDF extraction may contain headings, TOC repeats, tables or page-layout artefacts. M3 extraction validation is still required.
- No publisher-byte comparison was performed. Local SHA-256 establishes artifact integrity only.
- Intended research task is retrieval-augmented generation; **indexing documents is not fine-tuning/training LLM weights**.
- Non-ICH source licensing, especially pharmacopoeial monographs, requires separate review.
